# DSP 设计与取舍

## 目标音频特征

| 声源 | 特征 | 期望 |
|---|---|---|
| 环境风声 / 底噪 | 低频为主、持续、幅度平稳 | 压低 |
| 脚步 / 静步 | 短瞬态、80–200 Hz 基频 + 1–6 kHz 摩擦成分、幅度低 | 抬起 |
| 枪声 | 极高峰值、2–8 kHz 刺耳成分集中 | 削平但不吞掉方位信息 |

实测参考（48 kHz 立体声）显示风噪样本低频能量占比 71.5%、crest 约 4.3；枪声类瞬态 crest 显著更高。据此把「稳态性」与「瞬态性」作为两条主判据，而不是靠固定阈值门控。

## 处理链

```
输入 → [稳态噪声抑制] → [多段 EQ] → [瞬态/安静段提升] → [动态去刺 + 压缩限幅] → 输出
```

### 1. 稳态噪声抑制

双时间常数包络（快 6 ms / 慢 450 ms）作用于低通后的信号，`slow/fast` 比值作为「稳态度」。稳态度高的低频成分按 `wind` 系数抵消；同时对全频段施加弱的稳态衰减。瞬态因快包络远超慢包络而几乎不被削减，脚步因此得以保留。

### 2. 多段 EQ

`config.txt` 为 8 段滤波：140 Hz 高通压掉风声隆隆，220 / 420 / 1.6k / 3.2k / 6.5k 分段抬升脚步质感与方位线索，配 Preamp 负增益留出余量防爆音。四档增益表对应 UI 上的强度档位。

### 3. 瞬态 / 安静段提升

快 1.5 ms、慢 80 ms 包络比值得到瞬态度 `tr`，减去底噪基线后乘以 `footstep` 系数；安静段（慢包络低于 0.05）再乘 `quiet` 增益。两者都用「1 − 稳态度」门控，避免把持续噪声一起放大。

### 4. 动态去刺 + 压缩限幅

高频分量（去掉 1.8 kHz 低通后的部分）快慢包络比得到去刺量，按 `boom` 系数回削。压缩器 attack 3 ms / release 120 ms，阈值随 `boom` 下移；输出硬钳在 ±0.94，避免数字削波。

## 参数映射

UI 七个滑块 → `wind / eq / footstep_boost / quiet_boost_db / boom_threshold / output_gain / eq_db`，全部归一化到 0–1 后进入上式。Web 试听器与 Windows 控制面板共用同一套参数语义。

## 自检

`node selftest.js` 用合成信号验证方向性：风声 RMS −3.4 dB、脚步 RMS +2.9 dB、枪声 RMS −6.2 dB 且峰值从 1.020 降到 0.898；无 NaN、无硬削波。

## 为什么不做模板库匹配

内容感知降噪通常靠预先录制的稳态噪声模板做比对/重写，效果更强，但需要专有录音库与逐帧匹配。本项目改用「稳态估计」这一通用判据实现方向性效果，代价是对非平稳环境噪声只能做到七八成。想更近一步可自录环境噪声做 NLMS 自适应消去，或接 RNNoise / SpeexDSP。

## 为什么不自己写 APO 驱动

Windows APO 需要微软签名 + 提权注册到指定播放端点，家用环境不现实。本项目让 Equalizer APO 承担系统级音频链，自己只做控制面与配置下发，机制等价、部署成本低、可随时还原（写配置前自动备份）。

## 边界

- 稳态估计不是识别，无法区分「持续的风」与「持续的脚步摩擦」。
- 动态压缩会轻微降低整体动态范围，属有意为之。
- 只支持立体声；多声道环绕会让空间线索与 EQ 判据失配。
- 不读取游戏进程、内存或网络数据，仅处理系统音频输出。
