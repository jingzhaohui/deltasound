# DSP 设计与取舍（v1.1）

代码单一真源在根目录 `dsp-core.js`；本文描述其判据与参数。竞品对比和频段证据见 [RESEARCH.md](RESEARCH.md)。

## 目标音频特征

| 声源 | 特征 | 期望 |
|---|---|---|
| 环境风声 / 底噪 | <250 Hz 为主、持续、幅度平稳 | 压低，且不能被向上压缩重新抬起来 |
| 脚步 / 静步 | 三区：150–450 Hz 撞击 + 1–3.5 kHz 材质 + 4–9 kHz 瞬态；幅度低、L/R 有 ILD | 抬起，且**不改写 ILD**、保留远近层次 |
| 枪声 | 极高峰值、2.5–9 kHz 刺耳成分集中、起音极快 | 削平首峰但保留方位信息 |

## 第一原则：立体声联动

所有包络取自 `m = max(|L|,|R|)`，所有增益是标量并**同时乘到 L/R**；低频抵消取两声道中置分量，高频分解用共同中置低频。任何逐声道独立的压缩/限幅都会改写 ILD——而 HRTF 的左右定位正是靠 ILD + ITD，改了就等于「听得见但辨不出方向」。

自检里「纯联动档」（关掉去刺与风声抵消）ILD 偏差为 **0.000 dB**，用来回归这条原则。全链路因去刺保留共同中置低频，ILD 会向 0 收敛约 0.03 dB，属预期且可忽略。

## 处理链

```
输入 → [静态 9 段 EQ / Biquad] → [稳态噪声抑制] → [连续斜率向上压缩]
     → [侧信号 L−R 增强] → [枪声动态去刺] → [1.5ms 前瞻联动限幅 + tanh 软削波] → 输出
```

### 1. 静态 EQ（Equalizer APO / Web Audio 节点）

| 段 | 参数 | 作用 |
|---|---|---|
| Preamp | −6.5 dB | 总提升 >10 dB，先留 headroom |
| HPQ | 90 + 风声×50 Hz | 只切 <150 Hz 的爆炸 rumble（最强掩蔽源），**保留 150–450 Hz 脚步体感** |
| LSC | 120 Hz / −3.5 dB | 削减低频向上掩蔽。比提高频更有效，且不会让枪声变刺 |
| PK | 700 Hz / −2.0 dB / Q1.4 | shallow scoop 去箱声/浑浊 |
| PK ×5 | 220 / 420 / 1600 / 3200 / 6000 Hz | 三区脚步 + 距离线索，上限 +3 / +3.5 / +3 / +4 / +2.5 dB |
| HSC | 10 kHz / −1.0 dB | 只轻微去嘶；6–12 kHz 的距离线索要靠动态去刺保护，不能静态砍死 |

四档增益表在 `config.txt` 末尾。所有档位都必须配合后级限幅。

### 2. 稳态噪声抑制

低通 250 Hz 后的中置分量用双时间常数包络（6 ms / 450 ms）：`slow/fast` 比值即「稳态度」。稳态度高的低频按 `wind` 系数做中置抵消，全频段另乘弱的稳态衰减 `(1 − wind·0.8·steadAll)`。瞬态因快包络远超慢包络而几乎不被削减。稳态平方门控 `(1−steadAll)²` 同时阻止后级向上压缩把风声重新抬起来。

### 3. 连续斜率向上压缩（静步）

```
envDb   = 20·log10(慢包络)                    # 用慢包络而非瞬时样本，事件整体被抬
gate    = sigmoid(envDb − (−58 dBFS)) · (1 − 0.85·gunAct) · (1−steadAll)²
upDb    = clamp((−24 − envDb) · (1 − 1/2.5), 0, quiet·14 dB) · gate
gain    = 10^(upDb/20)，增益下降快(0.01) / 恢复慢(0.0005)
```

用连续斜率而不是硬门限：越微弱的声补得越多，但近/远仍保留层次（自检 11.9 → 11.3 dB），且大声音瞬间让增益快速归零，消除 pumping。`−58 dBFS` 底噪门保证极安静段不被拉高（自检 −4.8 dB）。阈值 −24 dBFS 是按「全带宽慢包络」标定；同类项目用带通包络 −32 dBFS，尺度不同。

### 4. 侧信号增强（侧向定位）

```
mid = (L+R)/2 , side = (L−R)/2
side *= 1 + sideSlider·0.585·footAct        # 上限约 +4 dB
L' = mid + side , R' = mid − side
```

只抬侧信号、不动中置、不引入时延，因此居中人声/枪声不会被拉宽，ITD 完全不变。`footAct` 只在脚步瞬态活动时高，且被枪声活动抑制。

### 5. 枪声动态去刺

高频带（>1.8 kHz 相对共同中置低频）的快/慢包络电平与瞬态差，经双 sigmoid 得到连续 `gunAct`：

```
gunAct = smooth( sigmoid(hfDb − (−26 dBFS)) · sigmoid((hfDb − hfSlowDb) − 5 dB) )
hfGain = 1 − boom·0.65·gunAct               # 最多约 −9 dB
```

只削高频、且只在枪声期削，起音方向信息保留；脚步频带几乎不触发。

### 6. 前瞻联动限幅 + 软削波

- 前瞻 1.5 ms（48 kHz 下 72 样本）：用「当前」峰值计算增益，施加到「1.5 ms 之前」的样本，因此能在枪声首峰到达前就开始压。
- 联动检测 `max(|L|,|R|)`，attack 0.2 ms / release 90 ms；阈值 `0.55 − boom·0.30`。
- 输出用 tanh 软削波（ceiling 0.89 ≈ −1 dBFS）而非硬钳，避免谐波失真造成的二次刺耳。

## 参数映射

8 个滑块（0–1 归一化）→ `body / foot / quiet / surface / detail / side / wind / boom`。前五个是各 EQ 频段的 dB 上限比例，`quiet` 同时是向上压缩的最大提升 dB，`side` 是侧信号增益，`wind` 是稳态抵消与高通拐点，`boom` 是去刺深度与限幅阈值。Web 试听器与 Windows 控制面板共用同一套语义。

## 自检

`node selftest.js`（require 同一份 `dsp-core.js`）：三方向 RMS/峰值、底噪门、纯联动 ILD、全链路 ILD、侧信号增益、远近层次、配置导出一致性。详细数值见根目录 README。

## 明确不做的

- **内容感知模板库匹配 / RNNoise**：需要专有录音库或语音训练模型；后者会把脚步/枪声当噪声削掉。稳态估计是通用判据，代价是对非平稳环境噪声只能做到七八成。
- **自己写 APO 驱动**：Windows APO 需微软签名 + 提权注册到指定端点。让 Equalizer APO 承担系统级链路，自己只做控制面与配置下发，机制等价、可随时还原。
- **物理回环硬件 / 进程级 loopback / ML 事件分类器**：门槛与复杂度不匹配本项目定位，见 RESEARCH.md 第四节。

## 边界

- 稳态估计不是识别，无法区分「持续的风」与「持续的脚步摩擦」。
- 去刺保留共同中置低频，会带来 <0.1 dB 的 ILD 收敛。
- 只支持立体声；多声道环绕会让空间线索与 EQ 判据失配。
- 不读取游戏进程、内存或网络数据，仅处理系统音频输出。
